# OtpremaOps — технический аудит и план до пилота

Проверено 28.09.2026 по исходникам в `H:\serbiya` и локальным тестам. Это не сертификация государственной интеграции и не приёмка промышленного развёртывания.

## Что уже сделано

Next.js/React приложение с PostgreSQL и Drizzle, ролями и изоляцией организаций, операционной очередью, CSV/XLSX импортом до 500 строк, сопоставлением полей и единиц, версионированными документами, журналом ошибок, аудитом и фоновым обработчиком. Демонстрационный сценарий подробно описан в `H:\serbiya\docs\DEMO.md`; интерфейс на сербском, английском и русском. В коде есть явная метка `DEMO / MOCK`.

## Блокеры продажи как рабочего eOtpremnica-клиента

1. `src/integrations/eotpremnica/adapters.ts`: только `MockEotpremnicaAdapter` выполняет обмен. `SandboxEotpremnicaAdapter` и `ProductionEotpremnicaAdapter` всегда возвращают ошибку конфигурации. Никакой государственной отправки нет.
2. `src/integrations/eotpremnica/xml.ts` создаёт `<OtpremaOpsDemoDispatch>`, а государственный интерфейс использует XML/UBL. [Официальное техруководство](https://www.eotpremnica.efaktura.gov.rs/tekst/5370/tehnicko-uputstvo-api-dokumentacija.php) и [примеры UBL](https://www.eotpremnica.efaktura.gov.rs/) доступны, но сериализатор и конформанс-тесты отсутствуют. Портал сообщает о версии 1.6.3 в продуктиве с 17.09.2026; PDF API на портале обозначен 1.6.0. Перед реализацией нужно сверить изменения версий.
3. `src/integrations/eotpremnica/types.ts`: текущий DTO содержит только номер, имена отправителя/получателя, PIB получателя, адрес назначения, дату и товары. [Статья 6 действующего закона](https://www.eotpremnica.efaktura.gov.rs/tekst/6751/zakon-o-izmenama-i-dopunama-zakona-o-elektronskim-otpremnicama-31082026.php) перечисляет также идентификаторы сторон, перевозчика, основание перемещения, места и времена погрузки/выгрузки, транспорт и дополнительные сведения. Обязательность каждого поля надо брать из действующих правил и официальных схем для конкретного сценария, а не просто копировать список закона.
4. `src/services/imports.ts`: после аудита добавлена группировка строк с повторяющимся номером отгрузки или внешним ID в один документ. Конфликт общих реквизитов блокирует всю отгрузку. Формат реальной выгрузки клиента ещё не получен: каждую позицию пока надо снабжать номером или ID, а сопоставление его колонок проверить отдельно.
5. В приложении нет рабочего цикла ePrijemnica и сверки с отправленной eOtpremnica. [FAQ министерства](https://eotpremnica.efaktura.gov.rs/tekst/6563/najcesce-postavljena-pitanja.php) указывает, что после поступления ePrijemnica поставщик принимает её для согласования. Для клиента это часть полного цикла.
6. `docs/SECURITY.md` перечисляет недостающие перед интернет-развёртыванием меры: хранение и ротация секретов, усиленная аутентификация/лимиты, резервное копирование и восстановление, мониторинг, политика хранения данных. Очереди также требуется сверка с внешней системой после неопределённого ответа или падения работника, чтобы избежать двойной отправки.

## Ворота разработки

| Этап | Конкретный результат | Приёмка |
| --- | --- | --- |
| 0. Воспроизводимая сборка | Восстановить зависимости и CI; поднять отдельную тестовую PostgreSQL. | `lint`, `typecheck`, `test`, `build` и e2e зелёные на чистом checkout; зафиксированы версии Node/pnpm. |
| 1. Реальная выгрузка | 2–3 обезличенных файла от пилота, группировка по номеру, контроль противоречивых общих полей, повторного импорта и ошибок отдельных строк. | Один многопозиционный документ из нескольких строк; повторный импорт не плодит дублей; тесты на реальных форм-факторах. |
| 2. Контракт документа | Версионированный DTO с обязательными полями для выбранного сценария, официальный UBL/XML сериализатор, проверка XSD/схем и контрольные примеры. | Файлы проходят официальные схемы и проверку на государственном демо-контуре; внутренний demo XML остаётся только для mock. |
| 3. Государственный демо-контур | Авторизация, отправка, асинхронные статусы, получение документа, обработка ошибок, изменения/отмена по поддерживаемым API. | Матрица исходов: принято, отклонено, таймаут, повтор, пропавший ответ, рестарт worker; сверка без дублей. |
| 4. Полный рабочий цикл | Получение/обработка ePrijemnica, подтверждение/отклонение и состояние согласования в UI и аудите. | Сквозной тест по двум сторонам в демо-контуре и утверждённый процесс клиента. |
| 5. Промышленный запуск | Безопасные учётные записи и секреты, мониторинг, резервные копии, инструкции на сбои, миграция и отдельная база клиента. | Протокол восстановления, контроль доступа и финальная приёмка клиентом; только затем `EOTPREMNICA_MODE=production`. |

Оценка: примерно 8–14 недель для 1 опытного full-stack разработчика и частичной занятости специалиста по сербским документам/QA после получения доступа к демо-контуру и файла клиента. Это оценка планирования, а не гарантированный срок; сложность UBL и особых сценариев может его увеличить.

## Проверка среды, которую удалось выполнить

Рабочее дерево `H:\serbiya` не имеет первого коммита: исходники показаны Git как неотслеживаемые. Изначально локальные зависимости содержали junction-ссылки на отсутствующий `E:\serbiya\node_modules`. Зависимости восстановлены по lock-файлу через Corepack/pnpm 10.15.1; проверка выполнялась на Node.js 24.14.0. Секреты в `.env` не изменялись; исходное дерево не сбрасывалось и не коммитилось. Первый коммит делать после просмотра всего пользовательского дерева.

| Проверка | Результат |
| --- | --- |
| Vitest на отдельной PostgreSQL 17.11 | **30 тестов прошли**: 21 unit и 9 интеграционных. Миграции применены к временной базе, не к базе проекта. |
| TypeScript / ESLint | Проверки прошли. |
| `next build --webpack` | Production-сборка прошла. Это проверка сборки, не доступности государственного API. |
| Playwright e2e | **Не выполнены**: запуск локального веб-сервера для тестов отклонён политикой среды. Добавлен тест многопозиционного импорта, но его прохождение не заявляется. |
| Государственный demo / production | **Не проверены**: рабочие адаптеры и официальный сериализатор отсутствуют. |

При остановке временной БД воспроизведено падение worker из-за необработанного события ошибки idle-соединения PostgreSQL. Добавлен обработчик, который не печатает объект клиента/параметры подключения, и регрессионный тест; время ожидания подключения ограничено 5 секундами. [Документация node-postgres](https://node-postgres.com/apis/pool#events) подтверждает необходимость обработчика `pool.on('error')`.

В Vitest добавлено явное включение записи только через `TEST_DATABASE_URL`: обычная база приложения больше не подхватывается тестами автоматически. Передача тестового URL по-прежнему требует отдельной, мигрированной тестовой БД. Сквозной браузерный тест и CI остаются частью ворот 0; не считать продукт готовым для релиза только по зелёной локальной сборке.

Временный worker завершён, тестовая PostgreSQL на порту 55433 остановлена. Удаление созданного для проверки каталога отклонено политикой среды; в нём остались скачанные бинарники, архив и тестовые данные: `C:\Users\koall\AppData\Local\Temp\otpremaops-verify-4d7840ee5f9b4221b92b734204039e65`. Пользовательскую базу проекта и стороннюю PostgreSQL не изменяли. Этот конкретный временный каталог можно удалить вручную после проверки, что никакой процесс им не пользуется.
